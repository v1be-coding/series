# Cloudflare as the security edge, CloudFront as the CDN

Every public subdomain is proxied through Cloudflare (orange cloud) in front of CloudFront, and each layer has one job. Cloudflare is the security edge: DDoS protection, bot filtering, and one rate-limiting rule in front of the app-level limits. The free plan allows one such rule per domain, so all episodes share it. It matches `/api/*` on every subdomain and works as a coarse flood guard per IP. Each episode's own limits live in the app. Caching is bypassed with a cache rule. CloudFront is the only cache and the only path into AWS: it serves the private S3 site and the Lambda API over HTTPS with an ACM certificate in `us-east-1`. Cloudflare connects in Full (strict) mode.

DNS-only (grey cloud) would have been simpler. We chose the proxy because the portfolio should show a real security edge. Splitting the jobs avoids the usual cost of stacking two CDNs: two caches to clear on every deploy, and HTTPS settings that loop.

## Consequences

- CloudFront accepts only traffic that came through Cloudflare. Cloudflare adds a secret origin header, and a CloudFront Function rejects any request without it. `v1be-infra` generates the header value and writes it to the Cloudflare rule and a CloudFront KeyValueStore, which the function reads at runtime, so CI never handles the value (ADR-0009). Without this lockdown, anyone with the raw `*.cloudfront.net` address could bypass the edge.
- The lockdown applies to production only. Branch environments are served from their raw `*.cloudfront.net` address with no Cloudflare in front. They're temporary and hold only seed data, so skipping the edge risks nothing. The smoke test runs there first, then again through Cloudflare on the production URL after the merge.
- Episode CI holds no Cloudflare token. A Cloudflare token can only be scoped to a whole domain, so one in episode CI could rewrite the portfolio's main records or email records. Only `v1be-infra`'s protected environments hold one, and they accept `main` alone (ADR-0012). Production DNS records, certificates and validation records come from `v1be-infra`: adding an episode to its list and applying creates them during Setup.
- `v1be-infra` builds the header-check function and the origin access control once per account, and the template repo's CloudFront module only references them. Any role that can write a function could attach the KeyValueStore and read the secret, and AWS has no permission that blocks this, so CI can't create or edit functions. Episodes use AWS's managed cache policies. An episode that needs its own edge logic changes `v1be-infra` during Setup.
